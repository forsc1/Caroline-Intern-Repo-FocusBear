## Reflection: 
# What steps can you take to ensure you handle data securely in your daily tasks?
To handle data securely, I must only access information I need for my work, and keep my accounts and devices properly protected through two-factor authentication and private network access only. I must also consistently review files I commit to GitHub and ensure I am not uploading private user data or unnecessarily copying it to third-party locations. Sensitive information such as API keys and tokens will never be exposed in code, screenshots, logs or public repositories.

# How should you store, share, and dispose of sensitive information safely?
Sensitive information should only be stored in approved and secure systems with appropriate access controls. I will ensure that it is only shared with authorised people in Focus Bear through approved communication channels such as the Focus Bear dashboard. When the information is no longer required, I will make sure that unnecessary copies are securely deleted rather than left on personal devices, cloud storage, or any other locations where they could be accessed accidentally.

 # What are some common mistakes that lead to data privacy issues, and how can they be avoided?
- Accidentally committing credentials to GitHub
- Sharing screenshots or logs containing personal information
- Sending information to the wrong person (unauthorised access)
- Using real user data when test data could be used
- Leaving my devices unlocked

These mistakes can be avoided by checking information before sharing it and using test or anonymised data where possible. Furthermore, following access controls and keeping devices and accounts secure will decrease the chance of accidental data breaches.

One habit I can adopt is to always review anything I am about to commit, upload, or share for sensitive information. For example, before submitting logs, I will check that they do not contain user information or other confidential data that can compromise the security of Focus Bear.

A key learning for me is that data security is part of everyday development work, not just something that applies to obviously sensitive information. I will follow a minimum-data approach by only accessing and sharing the information necessary for the task I am completing.
